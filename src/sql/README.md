# src/sql — SQL DDL and DBML interop

Everything here works on `RelationalModel` (src/model/types.ts) and is pure: inputs are treated as deeply readonly,
output never depends on Record key order, ids come from `newId`. Identifier quoting and dialect type mapping are
PRIVATE to this directory (`identifiers.ts`, `typeMap.ts`); no other module may build SQL text.

```ts
import { generateDdl, ddlIssues, parseDdl, parseDdlSafe, exportDbml, exportDbmlDetailed, importDbml, SqlParseError } from '@/sql';

generateDdl(model, 'postgresql' | 'sqlite' | 'mysql' | 'generic', opts?) -> { sql: string; issues: Issue[] }
ddlIssues(model, dialect)                       -> Issue[]            // codes ddl.<dialect>.*
parseDdl(text, dialect | 'auto' = 'auto', { name? }?) -> { model; warnings: Issue[] }   // throws SqlParseError
parseDdlSafe(...)                               -> { ok: true, model, warnings } | { ok: false, error }
exportDbml(model) -> string;  exportDbmlDetailed(model) -> { dbml; issues }               // codes dbml.export.*
importDbml(text, { name? }?)                    -> { model; warnings }                    // throws SqlParseError
class SqlParseError extends Error { line; column; offset; construct? }                    // 1-based line/column
```

Import warnings use codes `sql.import.*` / `dbml.import.*`; each carries `params: { line, column, construct }` and a
position-unique `id`. The imported model's `dialect` is the requested one, or (auto) inferred from signals (backticks /
AUTO_INCREMENT / ENGINE => mysql, [x] / AUTOINCREMENT => sqlite, SERIAL / IDENTITY / `::` => postgresql, else generic);
DBML imports are `generic`.

## DDL generation

* Output order is deterministic: relations in FK-topological order, ties by (name, id); inside a table columns keep model
  order, then PRIMARY KEY, UNIQUEs, CHECKs, FOREIGN KEYs (by first source column, name, target, id). Then
  `CREATE [UNIQUE] INDEX` statements, then deferred `ALTER TABLE ... ADD ... FOREIGN KEY`.
* Composite FKs are one clause; `REFERENCES T (a, b)` lists the target key in KEY order (`fkPairsInKeyOrder`), the source
  columns follow the same pairing.
* **FK cycles**: when the topological sort stalls, the lexicographically smallest remaining table is emitted and its FKs to
  not-yet-emitted tables are deferred to `ALTER TABLE ... ADD [CONSTRAINT n] FOREIGN KEY` after all tables.
  FKs whose target key is a unique INDEX (created after the tables) are deferred the same way in PostgreSQL/MySQL/generic.
  **Self references stay inline** (`CREATE TABLE t (... FOREIGN KEY (m) REFERENCES t (id))` is valid in every engine, so no
  ALTER is needed) — a deliberate deviation from "self references are cycles".
* **SQLite** has no `ALTER TABLE ADD CONSTRAINT`; it allows forward references in `CREATE TABLE`, so ALL FKs are inline
  (cycles included) and the table order is only cosmetic. Schema names are ignored (info `ddl.sqlite.schema-ignored`).
* Quoting: an identifier is quoted only if not `[a-z_][a-z0-9_]*` or a reserved word of the dialect (`generic` = union of
  all). `"` for postgresql/sqlite/generic, backticks for mysql; embedded quote characters are doubled. `quoteAll` option.
* Types: natively valid spellings are kept (INT, JSONB), other known types map to the dialect's canonical one (BLOB ->
  BYTEA, UUID -> CHAR(36) in MySQL, UUID/JSON -> TEXT in SQLite), integer display widths are dropped, MySQL VARCHAR without
  length gets 255 (warning). Unknown types and types with modifiers (UNSIGNED, WITH TIME ZONE, `[]`) are emitted VERBATIM
  with info `ddl.<d>.type-passthrough`. A column without a type inherits the referenced column's type for FK columns
  (info `type-inherited`); otherwise TEXT (MySQL VARCHAR(255)) with warning `missing-type`; SQLite emits no type.
* `DEFAULT` is the raw expression verbatim (MySQL non-literal defaults need their own parentheses — not added).
  Auto-increment columns never emit DEFAULT (warning `autoincrement-default`).
* Auto-increment: PostgreSQL and generic `GENERATED BY DEFAULT AS IDENTITY` (type must be SMALLINT/INTEGER/BIGINT);
  MySQL `AUTO_INCREMENT` (must lead an index, only one per table); SQLite `INTEGER PRIMARY KEY AUTOINCREMENT` inline —
  only for a single-column PK (error `ddl.sqlite.autoincrement-pk` otherwise); other integer types are emitted as INTEGER
  (info `autoincrement-type`) because only exactly INTEGER is a rowid alias.
* Indexes: PostgreSQL `USING method` + `WHERE` + `DESC`; SQLite `WHERE` + `DESC` (method dropped, info); MySQL `DESC`, method
  after the column list, **partial indexes are omitted with a warning** (never widened); generic keeps WHERE, drops method.
* Tables without a primary key are emitted (no engine requires one; `rel.no-primary-key` belongs to src/validation).
* **Refusal policy**: if any issue is an `error`, `sql` is `''`. Errors: dangling column/relation ids, empty/duplicate
  names, tables without columns, FK that does not reference a PK/UNIQUE/unique index (`fk-target-not-key`, all dialects),
  PostgreSQL/MySQL FK type mismatches, MySQL identifiers > 64 chars, MySQL TEXT/BLOB/JSON key columns, MySQL
  SET DEFAULT, MySQL SET NULL on NOT NULL, bad auto-increment configurations, duplicate index/constraint names.
  Warnings (PG identifier > 63 bytes, SQLite/generic type mismatch, partial index on MySQL, …) never block.
* **Name namespaces** (`duplicate-constraint-name`, `identifier-truncation-collision`): PostgreSQL = tables + indexes +
  PK/UNIQUE constraint names per schema, all constraint names per table, names compared after 63-byte truncation;
  SQLite = tables + indexes; MySQL = index/UNIQUE names per table, FK/CHECK names per database; `generic` = union.
* **DEFAULT**: SQLite/MySQL wrap anything that is not a plain literal (and, for MySQL, any non-NULL default on
  TEXT/BLOB/JSON) in parentheses (info `default-parenthesised`). PostgreSQL FK type rules follow PG 14 (TIME is its own
  family, int -> numeric/float ok, float -> numeric not); MySQL needs identical DECIMAL(p,s).
* The importer rejects a missing `;` (table options / index WHERE reaching a statement keyword) and unknown table options.
  MySQL `SERIAL` imports as `BIGINT UNSIGNED` + autoIncrement + UNIQUE (dialect must be given as `mysql`).
  `fulltext`, `spatial`, `exclude`, `if` are legal identifiers for the importer and are always quoted by the generator.

## DDL import (`parseDdl`)

Hand-written tokenizer (`lexer.ts`) + recursive-descent parser (`ddlParser.ts`); no regexes decide structure.

Supported: `CREATE [TEMP|UNLOGGED] TABLE [IF NOT EXISTS] [schema.]name (...)`; quoted names `"x"`, `` `x` ``, `[x]`;
`--`, `/* */` (and MySQL `#`) comments; many statements; columns with types (multi-word, arguments, `[]`, custom `"Type"`),
NOT NULL / NULL, DEFAULT expr, PRIMARY KEY (inline or table-level, composite, named), UNIQUE, REFERENCES (inline FK, optional
column list = target PK), CHECK (raw expression, `columnIds` filled when columns are mentioned), AUTO_INCREMENT /
AUTOINCREMENT / SERIAL family / GENERATED ... AS IDENTITY (normalised to base type + `autoIncrement`), COMMENT; table-level
`[CONSTRAINT n] PRIMARY KEY | UNIQUE [KEY] | FOREIGN KEY ... REFERENCES ... ON DELETE/UPDATE` actions, CHECK, MySQL
`KEY/INDEX n (cols)`; `ALTER TABLE [ONLY] t ADD [CONSTRAINT n] PRIMARY KEY|UNIQUE|FOREIGN KEY|CHECK|INDEX`, `ALTER COLUMN
SET DEFAULT | SET/DROP NOT NULL | ADD GENERATED ... AS IDENTITY`; `CREATE [UNIQUE] INDEX [CONCURRENTLY] [IF NOT EXISTS] n ON t
[USING m] (cols [ASC|DESC]) [WHERE p]`. FKs resolve in a second pass (forward references work).

Skipped WITH a warning naming construct and position: views, triggers/functions/procedures (bodies with inner `;` are
skipped as a unit), sequences/types/extensions/schemas, INSERT/UPDATE/DROP/SET/GRANT/LOCK/PRAGMA/COMMENT ON…, MySQL table
options (ENGINE=…, CHARSET…), COLLATE / CHARACTER SET, ON UPDATE CURRENT_TIMESTAMP, DEFERRABLE, MATCH, index prefix
lengths, index storage options (WITH/TABLESPACE/ALGORITHM), `OWNER TO`, TEMPORARY, `/*! … */` conditional comments.

`SqlParseError` (never a silent skip) for anything that would change the schema: computed/generated columns, unknown column
attributes (an unknown word after the type is NOT swallowed into the type), `CREATE TABLE AS/LIKE`, INHERITS, PARTITION,
`ALTER TABLE ADD COLUMN`/DROP/other actions, expression index keys, key prefix lengths in constraints, `DELIMITER`,
unknown/duplicate tables and columns, FK arity mismatch, FK to an undefined table/column, several primary keys, unterminated
strings/comments/parentheses. A FK to a non-key is imported with warning `sql.import.fk-target-not-key`.

## DBML

Export: `Table`, column settings `[pk, not null, unique, increment, default: x, note: '…']`, `indexes { }` (composite PK
`[pk]`, composite/named UNIQUE, plain indexes with `name`/`type`), `checks { }`, table `Note:`, one `Ref` per ForeignKey
(`a.(x, y) > b.(p, q)` for composite; `-` when the effective `fkCardinality().childMax` is `'one'`, else `>`; actions as
`[delete: …, update: …]`). Types containing spaces are quoted. Dropped with `dbml.export.*` issues: partial-index predicates,
DESC columns, FK labels, untyped columns (written as `text`), defaults/checks containing a backtick.

Import: `Table [schema.]name [as alias] [settings] { … }`, column settings above, `indexes`, `checks`, `Note`, `Ref [name]:`
/ `Ref { … }` blocks, inline `[ref: > t.c]`, composite refs, schema-qualified names, aliases, `''' multi-line '''` strings,
`//` and `/* */` comments. `>` many-to-one (FK on the left), `<` one-to-many (FK on the right), `-` one-to-one (FK on the
left). `fk.cardinality.childMax` is stored only when DBML states something `fkCardinality()` would not derive. `<>`
(many-to-many) has no physical FK in DBML: a junction table `A_B` with a composite PK and two FKs is generated and reported
(`dbml.import.many-to-many`). Ignored with a warning: `Project`, `Enum` (enum columns keep the enum name as type),
`TableGroup`, top-level `Note`, unknown table/column/ref settings, expression indexes. Errors: `TablePartial`/`~partial`,
unknown top-level keywords, unsupported default values, bad operators, undefined tables/columns.
A DBML `unique` index (no `type:`) imports as a `UniqueConstraint`; a unique `RelIndex` therefore comes back as a
`UniqueConstraint` after a round trip (semantically the same candidate key).

## Verification and limits

* SQLite DDL is EXECUTED in an in-memory `node:sqlite` database (`ddl.sqlite.test.ts`: composite FK enforcement,
  `PRAGMA foreign_key_check`, cycles, self reference, AUTOINCREMENT). If `node:sqlite` is unavailable the suite is skipped
  with an explicit reason in its title.
* PostgreSQL and MySQL output was NOT executed (no engine available): covered by golden files
  (`__golden__/pharmacy.*.sql`), inline goldens, and round-trips through our own parser. Treat dialect-specific rules above
  as reviewed-from-documentation, not engine-verified.
* Round-trip tests (`roundtrip.test.ts`, `dbml.test.ts`): model -> DDL/DBML -> model is structurally equal and the second
  export is byte-identical (fixpoint) for every dialect on the Pharmacy schema (composite PK/FK), self reference, FK cycle
  and a kitchen-sink model.
* Not supported: views/triggers as model elements, enums as types, computed columns, deferrable constraints, collations,
  index prefix lengths, expression indexes, `CREATE TABLE ... AS`, T-SQL specifics.
